Refactor Challenge

Day 4 — Week 7

The same grade calculator — written badly, then refactored. The refactored version is easier to read, easier to test, and easier to change later.

❌ Before — Messy

// magic numbers everywhere
// vague names, no error handling
// does 5 things at once

function calc(s) {
  let r = "";
  if (s >= 90) r = "A";
  else if (s >= 80) r = "B";
  else if (s >= 70) r = "C";
  else if (s >= 60) r = "D";
  else r = "F";
  document.getElementById("x")
    .innerHTML = "Grade: " + r;
  localStorage.setItem(
    "g", r);
  console.log(r);
  return r;
}

✅ After — Clean

// named constants, clear intent
// one function, one job
// proper error handling

const GRADE_THRESHOLDS = {
  A: 90, B: 80,
  C: 70, D: 60
};

function getLetterGrade(score) {
  if (score < 0 || score > 100) {
    throw new Error(
      "Score must be 0–100");
  }
  for (const [grade, min]
    of Object.entries(
      GRADE_THRESHOLDS)) {
    if (score >= min) return grade;
  }
  return "F";
}

function displayGrade(score) {
  const grade = getLetterGrade(score);
  updateUI(grade);
  saveGrade(grade);
}

What Changed & Why

✅Named constants — GRADE_THRESHOLDS instead of scattered magic numbers. Change the threshold once, it updates everywhere.
✅Meaningful names — getLetterGrade(score) tells you exactly what it does. calc(s) tells you nothing.
✅Single responsibility — getLetterGrade only calculates. displayGrade handles the UI. saveGrade handles storage. Each function does one thing.
✅Error handling — invalid scores throw a proper error with a clear message instead of silently returning a wrong grade.
✅Testable — the refactored getLetterGrade is a pure function. You can test it without touching the DOM or localStorage.
