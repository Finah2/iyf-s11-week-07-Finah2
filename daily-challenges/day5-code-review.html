Day 5 — Week 7

A self-review of the Week 6 Weather Dashboard using the peer review checklist. Honest assessment — what's good, what needs work, and what I'll fix next.

✅ What's Working Well

PASSAsync/await used correctly — all API calls use try/catch and every error is handled with a proper message to the user.
PASSLoading state handled — spinner shows while fetching, hides when done regardless of success or failure (using finally).
PASSlocalStorage for recent searches — last 5 searches saved and clickable. Survives page refresh.
PASS404 handled separately — city not found shows a friendly message, not a generic error.
PASSresponse.ok checked — we verify the response is successful before parsing JSON.

❌ Issues Found

FIXAPI key is hardcoded in JS — anyone can open DevTools and see it. In production this should be in an environment variable or proxied through a backend.
FIXNo input sanitization — the city input isn't trimmed or validated before sending to the API. A blank search hits the API and returns a 400 error.
FIXNo debounce on search — if this had a live search feature, every keystroke would hit the API. The delay function from Week 6 Day 1 should be used here.

⚠️ Improvements Needed

IMPROVEFunctions are too long — getWeather() does fetching, displaying, and saving. Should be split into smaller functions with one job each.
IMPROVEMagic strings — "hidden" class is repeated everywhere. Should be a constant: const HIDDEN_CLASS = "hidden".
IMPROVENo offline handling — if the network drops, the error message is generic. Could check navigator.onLine first and give a better message.
IMPROVEUnits toggle resets on new search — switching to Fahrenheit and then searching a new city switches back to Celsius. The preference should persist.
